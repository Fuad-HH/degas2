1. Download the DEGAS 2 tarball and unpack in your home directory.
   The most recent "stable" version is 4.6b.  
   One can access the code directly on
   the cluster at /u/ftp/pub/degas2 or via the URL
   ftp://ftp.pppl.gov/pub/degas2/degas2-4.6b.tar.gz

2. Begin reading the User's Manual, degas2_all.pdf in the degas2/Doc
   subdirectory.  The most useful chapters are 2 and 3.  Note that
   there is more detail in sections 2.2 and 2.3 than most users need.
   In chapter 3, you needn't read past the "Examples" section since
   that material is also advanced and somewhat out of date.  Also, you
   don't need to download the libraries since most of these are
   already installed on the PPPL cluster; see below, however.

3. Load needed modules and set Unix environment variables.  I have the
   following information in my .cshrc file (since I use tcsh).  If
   you're using a different shell, put it in the appropriate place so
   that these commands get invoked automatically.

		module load fweb
		module load pgf/11.10
		module load hdf
		module load netcdf
		module load totalview
		module load openmpi

		setenv LD_LIBRARY_PATH ${LD_LIBRARY_PATH}:/u/dstotler/hdf5/hdf5/lib
		setenv PATH ${PATH}:/u/dstotler/hdf5/hdf5/bin
#
# This was needed at some point for large parallel jobs
#
   setenv P4_GLOBMEMSIZE 268435456
#
# This forces totalview to use ssh to launch parallel processes rather
# than the default rsh.
#
   setenv TVDSVRLAUNCHCMD ssh

4. Create a DEGAS 2 run directory as in section 3.6 of the manual.  On
   the PPPL cluster, this should be called LINUX64.

5. Copy /u/dstotler/degas2/LINUX64/Makefile.local into that directory.
   Near the bottom of this file, the environment variable $(HOME)
   appears twice.  However, these point to libraries that I have
   installed for use with DEGAS 2.  For these pointers to work, you
   should replace $(HOME) with /u/dstotler.

6. Similarly, in your Makefile (in the src directory), set 
   TRIDIR=/u/dstotler/Triangle 
   However, Triangle is particularly easy to download and install,
   which one
   can do as described in Sec. 3.2.4 of the User's Manual.

7. Try running the Analytic_fluid_bench example (Sec. 3.7.1).  This 
   will check your installation and get you more familiar with the code. 

8. In particular, this will introduce you to the task of opening and 
   editing the  netCDF files that DEGAS2 uses for input and output.  
   Sec. 3.2.2 of the User's Manual explains how to set up Emacs so 
   that it can open and save these files. Note in particular that you
   will likely need to modify ncgen-filter to use ncgen3 rather than
   ncgen.

9. Proceed to the GPI example, Sec. 3.7.3.

10. At this point, one should begin considering visualization options.  The
    simplest and most effective is to use VisIt to open Silo-format files
    generated by the ucd_plot or geomtesta post-processors.  By
    default, these codes will create a file having the same root name
    as the run's output netCDF file and in the same directory, but
    with a .silo suffix.  All of the output variables are in this
    file, as will be apparent in VisIt (e.g., in the pseudocolor or
    contour plot types).    For purely 2-D problems, ucd_plot is
    preferable since it provides a full resolution vector plot in
    VisIt that can be zoomed as needed.  Moreover, the user does not
    need to generate an input file.  geomtesta can generate 3-D plots,
    as well as specified 2-D slices through 3-D geometries.
    Additional information on both codes are available in their
    preambles; see Doc/ucd_plot and Doc/geomtesta.pdf.

11. One would also benefit from browsing some of the other documentation in
    the Doc directory, in particular, definegeometry2d, defineback, outputbrowser,
    and sourcetest.

12. Running parallel jobs.  Only two executables contain MPI code: flighttest and
    postdetector.  To enable that code, one first needs to set MPI=yes in the 
    Makefile.local of the run directory, then:
    gmake clean
    gmake flighttest
    To compile or debug serial code after this, you will need to reset MPI=no,
    do "gmake clean" and remake as needed.

    For interactive batch jobs, you can use the "-I" option of qsub:

    qsub -I -lnodes=20,mem=1000mb -v DISPLAY -X -r n

    The user should assess the computational requirements for the run
    by timing a single processor run with about 1000 flights (via the
    "time" shell script built-in command) and scale the result to the
    desired run size.  The linearity of the run time of the code has
    been demonstrated to be linear up to about 200 processors.  The
    memory specification used here is needed only for the largest runs.

    Once the batch job is running, you can "cd" to your run directory and
    invoke mpirun directly:

    mpirun -np 20 flighttest

    The OpenMPI implementation of mpirun will recognize that you are running
    under the PBS system and access the list of assigned processors (in 
    $PBS_NODEFILE) automatically.

    A template for non-interactive batch jobs can be obtained upon request.
